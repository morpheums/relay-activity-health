## Findings (most severe first)

- [Minor] scripts/dev.sh:29 and :22-25 — A second Ctrl+C during cleanup can leave servers running. `trap 'exit 130' INT TERM` stays armed while `stop_all` runs from the EXIT trap. A second SIGINT calls `exit` inside the EXIT trap and aborts the tree kill part-way, which can orphan the `dotnet` or `ng serve` grandchildren. This is not a set-e defect, because the script is not tearing down at that point. Failing input: press Ctrl+C twice in quick succession while the API is shutting down. Fix: first line of `stop_all` is `trap '' INT TERM`.

- [Minor] scripts/dev.sh:41-54 — Readiness can be a false positive. If port 5080 is already served by a stale API, `curl` succeeds on the first pass and the `kill -0` check is never reached. The script then starts `npm start` against the old process while its own `dotnet run` has died with "address in use". Failing input: a previous API is still running on 5080. Fix: check `kill -0 "$api_pid"` before the `curl` in the loop, or fail early if 5080 is already answering.

- [Minor] scripts/dev.sh:33-35 — An interrupted `npm ci` leaves a partial `web/node_modules`. The next run skips install because the directory exists. Fix: test for `web/node_modules/.package-lock.json` instead, since npm writes it last.
