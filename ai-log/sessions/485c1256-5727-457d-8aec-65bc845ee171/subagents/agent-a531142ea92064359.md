## Final query texts
```sql
SELECT MAX(events.occurred_at) AS Value
FROM activity_events AS events
```
```sql
SELECT events.location AS Location, MIN(events.occurred_at) AS FirstActivityUtc
FROM activity_events AS events
WHERE events.account_id = @accountId
GROUP BY events.location
```
```sql
SELECT deduplicated.location AS Location, deduplicated.week_start AS WeekStart, COUNT(*) AS Count
FROM (
    SELECT DISTINCT
        windows.week_start,
        events.location,
        events.event_type,
        events.occurred_at,
        COALESCE(events.duration_seconds, 0) AS duration_seconds,
        COALESCE(events.outcome, '') AS outcome
    FROM OPENJSON(@windows) WITH (
        week_start date '$.weekStart',
        window_start datetime2 '$.startUtc',
        window_end datetime2 '$.endUtc'
    ) AS windows
    JOIN activity_events AS events
        ON events.account_id = @accountId
        AND events.occurred_at >= windows.window_start
        AND events.occurred_at < windows.window_end
    WHERE @eventType IS NULL OR events.event_type = @eventType
) AS deduplicated
GROUP BY deduplicated.location, deduplicated.week_start
```
```sql
SELECT accounts.id AS Id, accounts.name AS Name, accounts.timezone AS Timezone
FROM accounts
-- FindAsync: same text + WHERE accounts.id = @accountId
```
- **Parameters:** `@accountId int`, `@eventType varchar(40)` (NULL for `ActivityType.All`, otherwise the `SnakeCaseLower` name), and `@windows nvarchar(max)`.
- **Windows JSON:** it looks like `[{"weekStart":"2026-03-02","startUtc":"…Z","endUtc":"…Z"}]`. `Local` instants are converted to UTC and `Unspecified` ones are marked as UTC, so every instant carries a `Z`.
- **Result handling:** everything is materialised with `ToListAsync()`, and no query has `ORDER BY` or a trailing `;`.

## Deviations
- **Parameter style.** I used `SqlQueryRaw` with named, typed `SqlParameter` objects instead of interpolated `SqlQuery($"…")`, for two reasons:
  - The weekly query uses `@eventType` twice. Passing the same `DbParameter` instance twice through interpolation causes a duplicate-parameter error.
  - The queries have to be `const string` raw literals, and a `FormattableString` can't be const.

  No value is concatenated into the text; it is exactly the wire shape the battle test verified. If you want interpolation instead, the alternative is `events.event_type = COALESCE({eventType}, events.event_type)` with a non-const `FormattableString`.
- **`@windows` type.** It is `nvarchar(max)`, not `varchar`, because OPENJSON's native input is `nvarchar`. `@eventType` is `varchar(40)` to match its column.
- **Where the week start comes from.** Each window's JSON includes `weekStart`, and SQL returns it as the `date` `WeekStart`. SQL does no date arithmetic, which is what makes the Tokyo UTC-Sunday test pass.
