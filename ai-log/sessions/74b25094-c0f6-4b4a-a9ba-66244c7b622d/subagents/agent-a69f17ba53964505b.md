## Ruling on the self-reported deviations

1. **Weekday headers "M T W T F S S" — acceptable, but a design call.**
   - The mockup and Spec §6 show "Mon Tue …". Material hard-codes `getDayOfWeekNames('narrow')` for the visible glyph (`datepicker.mjs:1164`) and adds a visually-hidden long name in the same `<th>`. Screen readers therefore hear "Monday".
   - The "T T" and "S S" ambiguity is visual only. It could only be changed with a custom adapter or CSS hack.
   - **Needs the designer or user to accept it.**
2. **"Jul 2026" month label — not a real problem, but trivially fixable.**
   - Both the Spec and Picker mockups say "July 2026". The date-fns adapter's `monthYearLabel` is `'LLL uuuu'`, and Material upper-cases the text (`datepicker.mjs:2076`). The CSS lowercase/first-letter hack is what produces "Jul 2026".
   - Overriding `MAT_DATE_FORMATS.display.monthYearLabel` to `'LLLL yyyy'` would give "July 2026" and let the hack stay.
   - **Design call.** Only accept it if the user prefers not to touch the format provider.
3. **Material's caret and navigation buttons — acceptable.** Spec §6 says "Material's own labels", and C-31 keeps the defaults. The nav buttons are 40px against the Spec's 44px target, which is a nit.
4. **576px week group with about 15px wider gap — acceptable visually; minor.**
   - The real control is 561px (trigger fixed at 300px, stepper buttons content-sized). The extra gap is 15px, as measured from the screenshots.
   - Cleaner fix: give both stepper buttons a fixed width so the control is exactly 576px and matches the placeholder. Alternatively size the placeholder to the control.
   - **Design call** on whether 15px matters.
5. **Azure palette underneath the overrides — acceptable, with residual risk.**
   - Every visible calendar token I traced is overridden: selected, hover, focus, today outline, header, period and navigation icons. I saw no blue in the screenshots.
   - Any un-overridden Material token (ripple, state layers in the year view) would show azure and contradict Spec's "no brand accent". I did not exercise the multi-year view. Worth a quick manual check.
6. **Lazy-loaded dashboard route — acceptable, but it goes beyond PLAN and the redesign entry.**
   - Without it, the initial bundle would have been about 570 kB. That is above the 500 kB warning threshold and below the 1 MB error threshold.
   - Result: 364.6 kB initial plus a 205.8 kB lazy chunk. The cost is an extra request waterfall for a one-route app.

   - **Product call:** which route to take, and whether to record it in §13.
