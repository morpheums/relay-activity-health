DASH-247 · design spec v1 · for frontend

Calm ground, one answer, colour only where it means something.

  • Monochrome UI. Controls, selection and focus use ink on a warm-neutral ground. There is no brand accent.
  • Colour is only for status direction. Light red for above, blue for below, at different lightness, always with ▲/▼ and text.
  • One family. Geist 600 with tight tracking for the page title and the one number that answers Q1. Geist 400–600 for everything else, always with tabular lining numerals.
  • The server decides. Rows render in payload order. Counts and ranges are printed as given. Nothing on screen is computed on the client.

  • Layout: content max-width 1120 centred (160 gutters at 1440). Page padding 48 top / 64 bottom. Title → filters 28, filters → summary 32, summary → locations 24.
  • Cards: padding 32×40 (summary) and 24 (table cells). Rows are 56 high, or 64 for rows that wrap.

  • Elevation: cards have a 1px border and no shadow. Only the popover has a shadow: 0 16px 40px rgba(26,27,30,.14), 0 2px 6px rgba(26,27,30,.08).

  • Targets: every control, stepper button and day cell is at least 44×44.
  • Motion: popover fade and scale at 120ms, skeleton shimmer at 1.2s. Both are turned off under prefers-reduced-motion.

  1. Stepper buttons: C-18, unchanged. Disabled at the bounds, exactly as today.
  2. Trigger: shows the approved week label C-17, with aria-haspopup="dialog" and aria-expanded. Its accessible name starts with the visible text (proposal W-02). It is disabled when earliestWeek = latestCompleteWeek.
  3. Popover: a CDK overlay anchored under the trigger, role="dialog", with focus trapped. It closes on Escape, on an outside click or on a selection, and focus returns to the trigger.
  4. Period header: month/year view toggle plus previous/next month (Material's own labels). Next is disabled past latestCompleteWeek and previous before earliestWeek.
  5. Weekday row: Monday first (adapter locale weekStartsOn 1). The Monday column header is emphasised.
  6. Day cells: the other days render muted and aria-disabled. They cannot be selected.
  7. Selectable Monday: ink 600 on fill. Only Mondays from earliestWeek to latestCompleteWeek pass the dateFilter.
  8. Keyboard focus: 2px ink ring. Up/Down move 7 days, so from one Monday to the next.
  9. Selected Monday + week band: ink disc, with Tue–Sun on fill-muted via dateClass, so the whole week reads as one unit.
  10. Out of range: Mon Jul 27 is the current partial week. It is disabled like any other day.
  11. Helper text: proposals W-03 and W-04. The bounds come from the response and are never hard-coded.

7 · Picker library: Angular Material (confirmed)

Use: @angular/material MatCalendar (<mat-calendar>) inside a @angular/cdk/overlay cdkConnectedOverlay with cdkTrapFocus, opened by our own trigger button.

Bindings: [minDate]=earliestWeek · [maxDate]=latestCompleteWeek · [dateFilter]=Monday within the bounds · [dateClass]=Tue–Sun of the selected week · [selected]/[startAt]=week.start · (selectedChange) → close + weekSelected.emit(isoDate).

Adapter: provideDateFnsAdapter() from @angular/material-date-fns-adapter, with MAT_DATE_LOCALE = date-fns enUS and weekStartsOn: 1. API dates are parsed with parseISO as local calendar days, so there is no UTC shift. Theme through mat.datepicker-overrides with the tokens above.

Why: it is maintained by the Angular team and matches the app's Angular version. The keyboard grid and ARIA are already tested. It supports min, max, a filter and a per-day class, which is everything week-only selection needs, without a text input.

Rejected: mat-datepicker with an input (free typing; shows one date, not C-17). mat-date-range-picker with a custom MatDateRangeSelectionStrategy (non-Mondays stay clickable; the input format is two dates). Native <input type="week"> (ISO weeks rather than account-local Mondays; no Safari/Firefox desktop UI). PrimeNG / ngx-bootstrap (a second design system for one widget).

Selects stay native <select>, restyled with appearance: none and a chevron. They are accessible, the existing UI-44 tests use them, and they need no library.
